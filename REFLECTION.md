# Module 10 Reflection

Module 10 introduced me to the idea that input validation is also a security feature. Pydantic input validation ensures that only verified, non-malicious data is accepted by the application. Password hashing ensures there is no footprint of the bare-text password in the application or its backend and that there is no way to retrieve the text password from its hashed value. 
When we were introduced to PostgreSQL last week, I immediately downloaded the application since it was made clear that we would be using it for the rest of the semester. This is a habit of many years that has often led to a profusion of applications on my local machine. It later occurred to me that I could simply run PostgreSQL from the container while running the app and tests locally. This realization that I could use apps in containers seamlessly with apps on my local machine is something that I am still attempting to fully grasp. 

The volume mount for PostgreSQL had to be changed since more recent versions now use a slightly different convention. The biggest challenge with the assignment was the GitHub Actions security test. There were many security violations caused by outdated libraries. Where possible, I tried to update these libraries. Soon, a comprehensive refactoring of the existing code will be required to support current versions of all dependencies.
